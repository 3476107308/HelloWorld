### 9月17日（周四）｜ Day 1 ｜ 3h ｜ P0 ｜ 今天就是"开工日"

**【今天唯一目标】**
定义 `Transport` 抽象接口，并把 `MessageParser` 链路接上、编译干净。

**【三层拆解】**

① **数据对象**：`Transport` 抽象基类需要暴露哪些能力？先只回答"上层要什么"，不要想串口/TCP 的差异：
- 打开 / 关闭 / 是否已连接
- 发一批字节
- 收到字节（信号）
- 出错（信号）
- 连接状态变化（信号）

② **业务逻辑**（先写中文流程，再写代码）：
- 打开流程：`open()` → 参数是否合法 → 成功发 `opened()` / 失败发 `errorOccurred(msg)`
- 接收流程：底层 `readyRead` → `readAll()` → 发 `dataReceived(QByteArray)`
- 关键约束：**`Transport` 不知道 JSON，也不知道 UI。它只搬字节。**

③ **文件/声明**（今天要动的文件清单）：

| 类型 | 文件 |
|---|---|
| 新增 | `include/Transport.h` |
| 新增 | `include/TcpTransport.h`、`src/TcpTransport.cpp` `[必做]` |
| 新增 | `include/LoopbackTransport.h`、`src/LoopbackTransport.cpp` `[加分，用于自测]` |
| 改名 | `include/MessageParser.h` → `include/JsonLineParser.h`（类名同步改） |
| 修改 | `src/mainwindow.h/.cpp`：删掉无用的 `pending_`，把 `parser_` 接进 `simulateCommData()` |
| 修改 | `CMakeLists.txt`：加新文件 + `Qt6::Network` |

**顺手要修的 3 个已知问题（今天必须清掉）**：
1. `MessageParser::handleline` 拼写不规范 → 改名为 `parseLine`（连同调用处）。
2. `MessageParser::appendData` 里 `int pos; while((pos = ...) >= 0)` 在 C++ 里是赋值表达式，`-Wall -Wextra` 下要确认没有警告；更清晰的写法是把 `indexOf` 放在循环条件里，自己判断哪种更易读。
3. `MessageParser` 解析失败时**静默 return**（`MessageParser.cpp` 第 26、27 行）→ 改成发一个 `parseFailed(QString reason)` 信号，让上层能记日志。**"坏数据不崩溃但要留痕"是面试会问的。**

## 阶段 P3：亮点打磨（10/1 – 10/4）

---

### 10月1日（周四）｜ Day 15 ｜ 6h ｜ P3 ｜ **亮点核心**

**【今天唯一目标】** 分包算法（Framer）三种模式 + 自测用例。这是本项目最"工业级"的一块。
**【三层拆解】**
① 数据对象：`enum class FrameMode { Line, Timeout, LengthPrefix }` + `Framer` 类（内部缓冲区）。
② 业务逻辑：
- `Line`：按 `\n` 切（已有）
- `Timeout`：**超过 T 毫秒没有新字节到达**，就把缓冲区里现有内容当作一包吐出（需要定时器配合）
- `LengthPrefix`：先读固定长度的长度字段，再按长度取整包
- 三者都要处理：粘包（一次来 3 包）、半包（一包来 3 次）、长度字段本身被拆开
③ 文件：`include/Framer.h`、`src/Framer.cpp`、**`tests/framer_test.cpp`**（独立可执行目标，`add_executable` + `enable_testing()`/`add_test`）
**【验收标准】**
- [ ] 有**独立测试程序**，不需要开 GUI 就能跑
- [ ] 用例覆盖：单包 / 粘包×3 / 半包×3 / 空包 / 长度字段跨包 / 乱序脏数据后重新同步
- [ ] 测试全部通过，并在终端打印通过条数（截图留证）
**【最低可交付】** `Line` + `Timeout` 两种模式 + 至少 4 个用例。
