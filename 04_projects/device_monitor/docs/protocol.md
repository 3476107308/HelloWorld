# device_monitor 通信协议草案 v1

> 本文件是**上位机与设备（或模拟数据源）之间的数据传输约定**。
> 进入阶段 5（通信接入）前必须先完成本草案（README 要求）。

## 1. 目的与范围

- 定义"一条消息长什么样"以及"怎么判断一条消息的边界"。
- 适用传输方式：**串口（`QSerialPort`）优先**，后续可扩展 **TCP（`QTcpSocket`）**；**消息格式与传输方式无关**，换传输不用改协议。
- 目标：让**模拟数据**与**真实设备数据**走**同一套解析与更新逻辑**。

## 2. 传输层

- 串口（默认参数，接真设备时需与设备一致）：

| 参数 | 取值 |
|---|---|
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | None |
| 流控 | None |

- TCP（后续）：默认端口待定，消息格式不变。

## 3. 消息格式

- **文本 JSON**：一条消息 = **一个 JSON 对象**。
- 编码：**UTF-8**。

字段：

| 字段 | 类型 | 必填 | 说明 | 对应项目数据 |
|---|---|---|---|---|
| `id` | string | ✅ | 设备标识 | `Device::id_` |
| `temperature` | number | ✅ | 温度 | `Device::temperature_` |
| `voltage` | number | ✅ | 电压 | `Device::voltage_` |
| `online` | bool | ⬜ 可选 | 在线状态 | `Device::online_` |
| `ts` | number | ⬜ 可选 | 时间戳（毫秒） | 暂存/忽略 |

## 4. 边界规则（核心）

- **一条消息以 `\n`（换行，0x0A）结尾。**
- **一条消息只占一行**：序列化时**必须用 `QJsonDocument::Compact`**（紧凑、不含换行）。
  - 若用 `Indented`，JSON 内部会插入换行 → 会把一条消息切成多条 → **边界规则被破坏**。
- **接收方**：
  1. 收到的字节**先追加到缓冲区**（`QByteArray buffer_`）；
  2. **反复**在缓冲区中查找 `\n`：
     - 找到 → 取出"开头到 `\n`"这一段 = **一条完整消息**，并从缓冲区删除该段（含 `\n`）；
     - 没找到 → 说明**消息未收全**，留在缓冲区等下一次 `readyRead`。
- 该规则天然处理：
  - **粘包**（一次到达多条）→ 缓冲区有多个 `\n` → 循环切分多次；
  - **半包**（一条被拆开）→ 缓冲区无 `\n` → 留待下次。

## 5. 示例

发送两条消息（每条末尾 `\n`，此处以 `\n` 示意换行）：

```
{"id":"1","temperature":37,"voltage":3}\n
{"id":"2","temperature":52,"voltage":5}\n
```

## 6. 收发流程

- **发送**：`QJsonObject` → `QJsonDocument::toJson(QJsonDocument::Compact)` → 末尾追加 `"\n"` → `write()`。
- **接收**：`readyRead` 信号 → `buffer_ += readAll()` → `while(buffer_ 含 '\n')` 取出一段作为一条消息并从缓冲区删除 → 逐条解析处理。

## 7. 错误与容错

- **解析失败**（JSON 非法 / 不是对象）：**记录日志并丢弃该条**，继续处理后续消息（**不崩溃**）。
- **字段缺失**：使用默认值（`toString()`/`toDouble()` 的默认值），必要时记录日志。
- **打开设备失败 / 断线**：记录日志，停止读取；重连策略在实现阶段定义。
- **重新同步**：因边界为 `\n`，丢弃坏消息后**仍能从下一个 `\n` 正常切分**。
