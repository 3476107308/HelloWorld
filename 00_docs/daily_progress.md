## 6. 21 天总结（10/7 填）

**实际投入总时长**：约 **22 小时**（计划 106 小时）。分布极不均匀 —— 9/27（4.5h）、10/6（4h）、10/7（4h）三天占了 12.5 小时；9/28–10/4 有 7 天为 0。

**完成的功能**
- `Transport` 抽象接口 + `TcpTransport`（`QTcpSocket` 封装，对端断开不误报）
- `ConnectBar`：主机端口校验（1–65535）、四态状态灯、防连点、失败显示具体原因
- `DataView`：文本 / HEX 双模式、rx/tx 计数、发送区（可追加 `\r\n`）、显示区限长 500 行
- `JsonLineParser`：缓冲区 + 按 `\n` 循环切分，**正确处理粘包/半包**，解析失败不污染后续；**缓冲区 100 KB 上限保护**
- **多线程收发**：`IoWorker` + `moveToThread` 独立 `QThread`，跨线程队列连接，退出序列 `quit → wait → delete`
- `TempChartWidget`：`QPainter` 自绘温度折线，Y 轴刻度 + 网格，**范围随数据自适应**，绘图区裁剪，固定 60 点时间窗
- `TelemetryRecord` + **CSV 导出**：`QFileDialog` 选路径、`QTextStream` 逐行写、CRLF 行尾、取消/无数据两条边界、历史上限 1 万条
- `DeviceListModel`（Model/View 重构）、配置读写、日志双写（界面 + `run.log`）
- 工程化：`tools/build.ps1`（一键构建）、`tcp_feed.ps1`、`tcp_stress.ps1`、`tcp_framing_test.ps1`

**没能完成 / 砍掉的功能**
编码转换（UTF-16/GB2312/BIG5）、数据回放、曲线拖拽缩放、多套连接参数保存、`LengthPrefix` 分包模式、**串口真机路径**；另在第二次压缩中额外砍掉：曲线性能优化、批量刷新、通用字节收发与 TCP 双向、按设备分别记录历史、电压曲线、X 轴时间刻度。

**最有价值的 3 个技术点（面试要讲的）**
1. **多线程收发 + UI 不卡** —— 三重证据：100 KB/s 连续 25 秒 **零背压**、主线程 **CPU 0.1%**、`qDebug()` 打出**两个不同的 `QThread` 地址**（`0x…362e0 "Qt mainThread"` ≠ `0x…97d60`）
2. **粘包/半包的对抗性验证** —— 5 个用例（半包 / 粘包 / 逐字节 / 混合 / 容错），9 条零丢失、零乱序 + 1 条容错；**且知道自己的实现最坏是 O(k·n)、更好的做法是读游标**
3. **一次完整的性能优化闭环** —— 对照实验定位（同一根分栏把手：空文档流畅 → 1 万行后迟钝 → 清空又流畅）→ 根因（`QTextEdit` 无上限 + 逐包抄 1030 字符原文）→ 修复（换 `QPlainTextEdit` + 限长 500 + 不再逐包记录）→ **文本量 ↓25 倍、内存 269→49 MB**

**最大的卡点与解决方式**
- **节奏上的卡点**：9/28–10/4 停摆 7 天，9/28、9/30、10/4 三个检查点全部错过 → 10/5 触发第三次降级，**砍功能清单 1–6 全部砍掉**，范围收缩到「永不砍」七项，10/6–10/7 两天完成其中 5 项
- **技术上的卡点**：**"看起来对"的陷阱** —— 三次都是靠**逐条对账 / 逐字节验证**才分清"真问题"和"假问题"：① 测试脚本自己多打一个引号，让 41 变成解析失败（逐条对数才发现）② 数学上验证 CSV 是纯 CRLF（3834 / 95034 字节与理论值精确相等）③ Excel 截图里"空的 temperature 单元格"，靠选中看编辑栏（= 29）证伪
- **一句话**：**"看起来对"和"确实对"是两回事；能被数字验证的结论才算结论。**
