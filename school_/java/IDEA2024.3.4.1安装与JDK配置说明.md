# IDEA 2024.3.4.1 安装 + 用上 JDK 25（Windows）

> 对应老师《Idea下载安装.docx》的流程。目标：让 IDEA 用上你已经装好的 JDK 25，能写、能跑。
> 每一步同样三段：**做什么 → 为什么 → 该截哪张图**。

---

## 0. 先分清三个角色（这一步想通了，后面全通）

| 角色 | 是什么 | 在你的机器上 |
|---|---|---|
| **JDK** | 整套开发包：**编译器 `javac`** + **运行环境 `java`/JVM** + 标准类库 + `jar`/`jshell`/`jmods` 等工具 | `C:\Program Files\Microsoft\jdk-25.0.4.101-hotspot\` ✅ 已装 |
| **JVM** | 真正"执行"字节码的引擎（`java` 命令只是启动器） | 随 JDK 自带 |
| **IDEA** | 编辑器 + 工程管理 + 调试器。**它自己不会编译**——你点运行时，它在后台替你敲 `javac` 和 `java` | ⬜ 待装（解压版） |

> 一句话：**JDK 是发动机，IDEA 是驾驶舱和仪表盘。**
>
> 关于"解释器"这个词：准确说法是——`javac` 把 `.java` **编译**成 `.class` 字节码；`java` 启动 JVM，JVM 把字节码**执行**掉。现代 JVM 是"解释执行 + JIT 即时编译"混合，**不是纯解释器**，但它确实负责"跑"这一半。初学阶段把 JDK 理解成"编译器 + 运行环境"，够用。

## 1. 下载（Community 版 · 解压版 zip）

**老师指定的入口**：<https://www.jetbrains.com/idea/download/other.html>

那个页面从上到下是几组按钮，**按这个顺序点**（2026-09-15 实战确认过，很容易点错）：

| 步骤 | 点哪里 |
|---|---|
| 1 | 顶部 `Version` 下拉框 → **2024.3.4.1** |
| 2 | 第二排平台标签 → 保持 **Windows** |
| 3 | **第三排版本标签 → 点 `Community Edition`**（页面默认高亮的是 `Ultimate Edition`，那是收费/试用 30 天的，**必须切过来**） |

> 1. **忘了切 Community** → 下成 Ultimate（到期弹激活窗口）

> 3. **点了最后一行 `Sources Archive (zip)`** → 那是 **IDEA 自己的源代码包**（给想研究或自行编译 IDEA 的人用），解压出来**根本不能运行**
>
> **判定方法（最可靠）：看文件名。** 正确的是 **`ideaIC-2024.3.4.1.win.zip`**（`IC` = Community，`IU` = Ultimate，带 `sources` 的是源码包），大小约 1 GB 出头，源码包明显更小。

**直链**（按 JetBrains 官方命名规则拼的，失效就用上面那个页面）：

```
https://download.jetbrains.com/idea/ideaIC-2024.3.4.1.win.zip
```

- `IC` = **I**ntelliJ IDEA **C**ommunity（免费）；`IU` = Ultimate（**要付费/试用 30 天，别下错**）。
- 文件约 **1.1 GB**，下载完是个 `.zip`（不是 `.exe` 安装包——老师要求的就是这种解压版）。

   | 用户协议 | **勾选同意** → Continue | — |
   | 数据共享（发送匿名统计） | 随便选 | 不影响使用 |
   | ⚠️ 登录 / 激活 / 试用窗口 | **不该出现** | 出现就说明下成 **Ultimate** 了；Community 版不需要账号和激活 |

   > 关于「导入设置」的两个选项：选 `PyCharm Professional 2025.3` → 继承 PyCharm 的配置；选 `Visual Studio Code` → **把 IDEA 快捷键换成 VS Code 键位**。它们只是"检测到本机装过"，不是在要求你装。
3. **做桌面快捷方式**（解压版**不会**自动创建，得自己来）：
   - 打开 `D:\ideaIC-2024.3.4.1.win\bin` → 右键 **`idea64.exe`** → **「发送到」→「桌面快捷方式」**
   - ⚠️ **不要**用右键菜单里的「创建快捷方式」——那个会在**原地**生成"idea64.exe - 快捷方式"，桌面上看不到
   - ⚠️ **不要**把 `idea64.exe` 直接拖到桌面——那是**复制程序本体**，IDEA 会找不到自己的文件
   - 回到桌面重命名为 `IntelliJ IDEA 2024.3`
   - 固定到任务栏：**先双击启动 IDEA**，再右键任务栏上的 IDEA 图标 →「固定到任务栏」
   - 验证：真快捷方式图标**左下角有个小箭头** ↗

   | 项目开着想换 | IDEA 里 `文件 → 打开最近的文件` |

## 4. 新建项目（最关键的一步：选 JDK）

`New Project` 之后，重点看这几项：

| 字段 | 怎么填 | 为什么 |
|---|---|---|
| **Name** | 例如 `Lab01` | 项目名，**建议纯英文** |
| **Location** | 建议 `D:\AAA study\school_\java\idea-projects`（项目名会自动拼在后面 → `...\idea-projects\Lab01`） | 用 IDEA 默认的 `C:\Users\chengang\IdeaProjects` 也行（老师就是默认）。建议单独建 `idea-projects`：**和 VS Code 用的 `projects\` 分开放**——两个 IDE 对"源根目录""编译输出目录"的认定不同（VS Code 用 `bin\`，IDEA 用 `out\`），挤在同一个文件夹里初学阶段容易互相干扰 |
| **Build system** | 选 **IntelliJ** | 别选 Maven/Gradle——实验用不上，还会触发联网下载依赖 |
| **JDK** | 看下拉框里有没有 **25.0.4.1 / Microsoft OpenJDK 25** | 这就是你刚装的环境 |
| **Add sample code** | 勾上（可选） | 会自带一个带 `main` 的类，方便马上点运行 |

**如果下拉框里没有 JDK 25**（很可能没有）：
选 `Add JDK...` → 在文件浏览器里定位到 **`C:\Program Files\Microsoft\jdk-25.0.4.101-hotspot`** → 选这一层目录 → OK。
> ⚠️ 注意选**到 `bin` 的上一层**，也就是那个里面直接有 `bin`、`lib`、`conf` 的文件夹。
> 为什么可能没有？IDEA 只会自动扫描少数几个标准位置（`C:\Program Files\Java`、Adoptium 等），微软这套装在 `C:\Program Files\Microsoft\` 下，**大概率扫不到，要手动指**。

然后点 **Create**。

> 📸 **截图点 ②**：New Project 界面上 **JDK 那一栏显示 25**（这张图证明"IDEA 成功用上了 JDK 25"）。

## 5. 写第一个类并运行

1. 左侧项目树里，**`src` 上右键 → New → Java Class**
2. 输入类名：**`Hello`**（首字母大写、**不要自己打 `.java`**，IDEA 会加）
3. 在类里输入 `main` 然后按 **Tab**（或输 `psvm`），自动补出 `public static void main(String[] args) { }`
4. 在花括号里写：
   ```java
   System.out.println("你好，Java 25！");
   ```
   打 `sout` 再按 Tab 也能秒出 `System.out.println();`
5. 点代码行号左边的**绿色三角 ▶** → `Run 'Hello.main()'`（快捷键 `Ctrl+Shift+F10`）
6. 下方 **Run 窗口**出现输出 → 成功

## 6. IDEA 点 Run 的时候，背后到底发生了什么（和命令行对照）

它其实替你执行了类似这样的两条命令：

```
javac -d out\production\Lab01 src\Hello.java      ← 编译（用的是 JDK 25 的 javac）
java  -cp out\production\Lab01 Hello              ← 运行（用的是 JDK 25 的 java）
```

（在 IDEA 的 Build / Run 窗口第一行能看到它打印的完整命令行。）

**所以你命令行学到的东西一点没白学**：IDE 只是把"敲命令"这一步自动化了，你在第 7 节学的 `javac → .class → java` 那条链路，在 IDEA 里**一模一样地发生着**，只是被按钮藏起来了。

## 7. ⚠️ 兼容性：IDEA 2024.3.4.1 可能"不认识" JDK 25

**原因**：IDEA 2024.3 发布于 2024 年底，而 JDK 25 是 2025 年 9 月的——**IDE 比 JDK 老**。JetBrains 的[官方支持列表](https://www.jetbrains.com/help/idea/2024.3/supported-java-versions.html)是按版本列的，2024.3 时代还没有 Java 25。社区里有人撞到过同类报错（[JVM target 25 issue with IntelliJ](https://stackoverflow.com/questions/79999628/jvm-target-25-issue-with-intellij)）。

**典型症状**：
- `File → Project Structure → Project → Language level` 里最高只到 **23/24，没有 25**；
- 编译时报：`无法编译为 JVM 目标 25 配置的模块 ... IDE 不支持当前与该模块关联的 JDK`。

### 决策树（按顺序试，别一次做太多）

| 情况 | 怎么办 |
|---|---|
| **① 能选 25、能跑通** | 🎉 什么都不用改，继续用 |
| **② 认得了 25，但语言级别上不去 / 报 JVM 目标 25 的错** | `File → Project Structure → Project`，把 **Language level 改成 21**（**SDK 保持 JDK 25 不动**）。编译仍由 javac 25 完成、按 Java 21 的语法标准检查——**你实验里的代码完全够用** |
| **③ IDEA 干脆不认这个 JDK** | 把 **Project SDK 换成 JDK 21**：`C:\Program Files\Android\openjdk\jdk-21.0.8`（Android Studio 自带的，IDEA 2024.3 完整支持）。命令行那边仍然是 JDK 25，**两边互不影响** |
| **④ 想彻底顺** | 升级到 IDEA 2025.2+（完整支持 Java 25），或 `winget install JetBrains.IntelliJIDEA.Community`。代价：界面和老师文档略有差别 |

> **建议：先按 ① 试。报什么错就原样发我，我带你走 ②/③。**

### 🔬 2026-09-15 实测铁证：`JDK_X`

本项目 `.idea\misc.xml` 里实际写的是：

```xml
<component name="ProjectRootManager" version="2"
           languageLevel="JDK_X" default="true"
           project-jdk-name="ms-25" project-jdk-type="JavaSDK">
```

**`languageLevel="JDK_X"` —— 这个 `X` 就是 IDEA"不认识这个 JDK 版本"的占位符。** 它带来两个后果：

1. 右下角弹「**实验性功能警报**」（要求接受测试版 Java 规范条款）；
2. 编译和运行时被**自动加上 `--enable-preview`**（在 Run 窗口第一行能看到）。

两种都"能用但不干净"。**修法**：

```
Ctrl+Alt+Shift+S  →  左侧「项目」  →  Language level 选 21  →  应用
```

> ⚠️ **别选「SDK 默认」**——那等于"跟着 JDK 25 走"，又会回到 `JDK_X`。要**手动指定 21**。
> 改完后：`--enable-preview` 消失、实验性警告消失，SDK 仍是 JDK 25，编译仍由 javac 25 完成。

### 「以后每个新项目都要改吗？」

**不一定非得改**——不改也能编译运行（`JDK_X` 只是"按预览语义编译"，你已经实测跑通了）。但 `--enable-preview` 不干净，建议改。四种做法：

| 方案 | 操作 | 代价 |
|---|---|---|
| **① 每个项目改一次**（最直接、推荐） | 建完项目 → `Ctrl+Alt+Shift+S` → 「项目」→ Language level = 21 | 30 秒、两下点击，每个实验做一次 |
| **② 设为"新项目"的默认** | 找 `文件 → 新项目设置 → 结构…`（File → New Projects Setup → Structure…）。**菜单里若没有这一项，说明 2024.3 不提供** | 需当场确认菜单 |
| **③ 升级 IDEA**（最彻底） | 换 IDEA Community **2025.2+**（完整支持 Java 25）→ 新项目语言级别自动就是 25，永远不用改 | 界面与老师文档略有差别；可与老师版并存 |
| **④ 新项目改用 JDK 21 当 SDK** | IDEA 认识 21 → 语言级别自动 21、无预览、无警告 | 需装一个正规 JDK 21（Android Studio 那个只能应急） |

**本课最省事的建议：用 ①。** 你的实验代码（数据类型、运算符、循环、类）在 Java 21 和 25 下**完全一样**，改语言级别不影响任何实验内容。

> 📌 这是"**IDE 比 JDK 老**"的通病，不是你的操作问题——有人问过一模一样的问题：[OpenJDK 17 GA in IntelliJ: Why no v17 language level? Only "X - Experimental Features"](https://stackoverflow.com/questions/69187819/openjdk-17-ga-release-in-intellij-why-no-v17-language-level-only-x-experime/69187928)。
> 那个 `X - 实验性功能`（内部 ID 就是 `JDK_X`）正是 IDEA 为"比自己新的 JDK"准备的兜底档位。
> 注意：这个坑**只影响 IDE**，命令行（第 7 节那套）完全不受影响——实验1 任务1 本来也只要求装好环境 + 截图。

你 C 盘还剩 145 GB，**现在完全不用管**。真要搬家属于进阶操作：在 `bin\idea.properties` 里改 `idea.system.path` / `idea.config.path` 指向 D 盘。

## 9. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 运行按钮是灰的 | 当前类没有 `main` 方法，或 SDK 没指定 | 检查 `public static void main(String[] args)` 是否写对 |
| 提示 `Project SDK is not specified` | 建项目时没选 JDK | `File → Project Structure → SDKs → Add JDK` |
| 下拉框里找不到 JDK 25 | IDEA 自动扫描范围有限 | `Add JDK...` 手动指到 `C:\Program Files\Microsoft\jdk-25.0.4.101-hotspot` |
| 弹出登录 / 试用激活窗口 | 那是 **Ultimate** 版的提示 | 确认你下的是 **Community（IC）** 版 |
| 第一次打开很卡 | 正在建立索引 | 等它转完，别强退 |
| 中文输出乱码 | 少见——IDEA 默认就是 UTF-8 | `Settings → Editor → File Encodings` 全设 UTF-8 |
| 类名和文件名不一致报错 | Java 要求 public 类名 == 文件名 | 用 IDEA 的 New → Java Class 创建就不会错 |

你已有 **Code Runner**，它内置的 Java 执行器就是命令行那两条命令：

```
cd $dir && javac $fileName && java $fileNameWithoutExt
```

打开 `.java` 文件 → **Ctrl+Alt+N** 即可运行。

> ⚠️ 两个前提：① **先重启 VS Code**——它若是在装 JDK **之前**启动的，进程里的 PATH 还是旧的（环境变量只在进程启动时读取）；② Code Runner 只能"跑"，**没有补全、没有错误提示**。

### 正经写 Java：装 Java 扩展包

1. 重启 VS Code → `Ctrl+Shift+X` → 搜 **`Extension Pack for Java`** → 安装
   **认准三处**（插件市场里有山寨货）：标题 `Extension Pack for Java`、**发布者 Microsoft（带蓝色认证徽章 + microsoft.com）**、下载量几千万。**只认发布者，不要认名字像不像。**
2. 它是**"扩展包"**——本身不含功能，会连带安装 6 个扩展（语言支持 Red Hat、调试器、测试运行器、Maven、项目管理、IntelliCode）。点开「**扩展包(6)**」那一栏能看到清单。
3. **装完还会再下载一个几百 MB 的 Java 语言服务器**（右下角有进度），**等它跑完再动手，别关窗口**。
4. `Ctrl+Shift+P` → **`Java: Create Java Project`** → 选 **No build tools** → 选一个空目录
5. 它会通过 `JAVA_HOME` 自动找到你的 JDK 25（系统变量已配好）；想确认它认到几个 JDK，用 `Ctrl+Shift+P` → **`Java: Configure Java Runtime`**
6. 新建 `Hello.java` → `main` 方法上方出现 **▷ Run** → 点它运行

> 💡 在 VS Code 里看 `.md` 文档时按 **`Ctrl+Shift+V`** 打开排版预览，表格和标题会正常显示。

### 和 IDEA 的差别（为什么课程仍推荐 IDEA）

- VS Code 是**通用编辑器 + 扩展**架构：Java 能力靠插件，工程模型（SDK、模块、classpath）要手配 `settings.json`——就像你现在配 C++ 那样；
- IDEA 是**Java 原生 IDE**：Project SDK、运行配置、重构、断点调试开箱即用，且和老师的操作步骤一一对应；
- **教学一致性**：老师照着 IDEA 讲，你用别的工具，出问题没人能对上你的屏幕。

> 🔑 记住这个类比：你写 C++ 用的是「VS Code 当编辑器 + MSYS2 的 g++ 当编译器」；写 Java 就是「VS Code 当编辑器 + JDK 的 javac 当编译器」——**同一个套路，只是换了发动机**。

## 12. 速查：VS Code ↔ IDEA 对照（2026-09-15 实测）

### 快捷键对照（从 VS Code 过来最容易懵的几个）

| 操作 | VS Code | IDEA |
|---|---|---|
| 命令面板 / 查找操作 | `Ctrl+Shift+P` | **`Ctrl+Shift+A`**（Find Action） |
| 打开设置 | `Ctrl+,` | **`Ctrl+Alt+S`** |
| **运行当前文件** | `Ctrl+F5` | **`Ctrl+Shift+F10`** |
| 项目结构（SDK / 语言级别） | 无对应（改 settings.json） | **`Ctrl+Alt+Shift+S`** |
| 快速修复 / 建议 | `Ctrl+.` | **`Alt+Enter`** |
| 按文件名找文件 | `Ctrl+P` | `Ctrl+Shift+N` |
| 按类名找类 | `Ctrl+T` | **`Ctrl+N`** |
| 全局搜索文本 | `Ctrl+Shift+F` | `Ctrl+Shift+F`（一样） |
| 格式化代码 | `Shift+Alt+F` | `Ctrl+Alt+L` |

> 记不住快捷键没关系：**`Ctrl+Shift+A` 输入你想干的事的英文**（如 `run`、`sdk`、`structure`），IDEA 会把对应命令和快捷键一起列出来——这就是 IDEA 的"命令面板"。

### 两个 IDE 运行时实际执行的命令（本质完全一样）

**VS Code 跑的**（你截图里那行）：
```
& 'C:\Program Files\Microsoft\jdk-25.0.4.101-hotspot\bin\java.exe' -cp 'D:\AAA study\school_\java\projects\Lab01\bin' 'Hello'
```

**IDEA 跑的**（Run 窗口第一行，形如）：
```
C:\Program Files\Microsoft\jdk-25.0.4.101-hotspot\bin\java.exe -Dfile.encoding=UTF-8 -classpath "...\out\production\Lab01" Hello
```

**三处共同点**：
1. 同一个 `java.exe`（来自你的 **JDK 25**）；
2. `-cp` / `-classpath` 指向**编译产物目录**——VS Code 是 `bin\`，IDEA 是 `out\production\Lab01\`，**目录名不同，作用完全相同**；
3. 结尾都是**类名 `Hello`**，不带 `.class`。

**结论**：两个 IDE 只是在替你敲同一套命令。你命令行学会的东西，在哪儿都通用。

## 13. 首次进入 IDEA 你会看到什么（2026-09-15 实战遇到）

| 看到的东西 | 它是什么 | 怎么办 |
|---|---|---|
| `Main.java` 里的 `Hello and welcome!` + for 循环 | 建项目时勾了 **`Add sample code`**，IDEA 自动生成的**示例代码**（不是你写的） | 直接改成你自己的内容，或删掉新建类 |
| 代码里夹着的**蓝色斜体字** | **新手引导提示，不是代码！** 三句分别是：`Shift+F10` 运行 / `Alt+Enter` 看修正建议 / `Shift+F9` 调试 + `Ctrl+F8` 加断点 | 完成对应操作后自动消失。**它们不会被编译**，也不会出现在你复制出去的代码里 |
| 行号左边一个**红点** | **断点（Breakpoint）**——提示里那句"我们已经设置了一个断点"说的就是它 | 点一下即可取消（或光标移到那行按 `Ctrl+F8`）。**`Shift+F10` 运行不受影响；`Shift+F9` 调试会停在那儿** |
| 右下角 **「实验性功能警报」** | ⚠️ **这就是 IDEA 2024.3.4.1 不认识 JDK 25 的具体表现**：它给项目套了"预览版（preview）语言级别"，并要求你接受测试版 Java 规范的法律条款 | `Ctrl+Alt+Shift+S` → 左侧「**项目**」→ **Language level 改成 `21`**（任何不带 `Preview` 的都行）→ 应用。编译仍由 JDK 25 的 javac 完成，实验代码完全够用 |
| 项目树里的 `.idea\` | IDEA 自己的项目配置文件（存 SDK、语言级别等） | 别手动改；**交作业不用交它** |
| 项目树里的 `.gitignore` | 给 Git 用的忽略清单 | 现在用不到，不用管 |
| 项目树里的 `外部库` | JDK 的标准类库（你的 `System.out` 就来自这里） | 不用管 |
| 右上角「当前文件」+ ▶ / 🐞 | 运行配置选择器：▶ = 运行，🐞 = 调试 | 直接用 `Shift+F10` 更省事 |

### ⚠️ 你的 IDEA 项目被建在 VS Code 项目的**里面**了

实际目录结构：

```
D:\AAA study\school_\java\projects\
  Lab01\                    ← VS Code 项目（我建的）
    .vscode\settings.json
    bin\Hello.class         ← VS Code 的编译产物
    src\Hello.java          ← VS Code 里跑通的那个
    Lab01\                  ← IDEA 项目（嵌套在这里）
      .idea\
      .gitignore
      src\Main.java         ← IDEA 里的示例代码
```

**机制**：新建项目时 **`Location` 填的是"父目录"，IDEA 会在它下面用 `Name` 建一个子文件夹**。你当时 `Location` 选了 `...\projects\Lab01`、`Name` 填了 `Lab01`，于是变成 `Lab01\Lab01`。

**影响**：
- 能用，两个项目互不干扰（IDEA 的项目根是内层那个）；
- 但**在 IDEA 里看不到 VS Code 的 `Hello.java`**（它在外层，不属于 IDEA 项目）；
- 找文件时容易懵。

**下次建项目这样填**：`Location` = `D:\AAA study\school_\java\idea-projects`，`Name` = `Lab01` → 得到 `idea-projects\Lab01`（不再嵌套）。

现在这个不用重做——想干净点的话，先完全关闭 IDEA，再把内层 `Lab01` 文件夹整个剪切到 `idea-projects\` 下即可（IDEA 下次打开时选新路径）。
