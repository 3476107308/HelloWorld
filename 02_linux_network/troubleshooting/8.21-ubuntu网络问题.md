# ubuntu网络问题
## 相关报错信息解读
给8.8.8.8发送数据包后 得到Destination Host Unreachable 说明无法连接主机 错误来自192.168.43.134
查看默认网关 再给默认网关发数据包 发现也是失败的 因此问题在于ubuntu和vmware虚拟网关之间的问题 并不是外部网站的问题 先核查vmware设置 确保是NAT 已连接 启动时连接 然后在windows的cmd中用ipconfig查看 会发现VMnet8的ip地址和 ubuntu中使用的ip地址不一样，说明ubuntu中的静态ip配置和VMware当前NAT网段不匹配 

## 相关指令
ping -c 4 8.8.8.8 发4个数据包给8.8.8.8
ip addr 查看网卡和ip地址
ip link 查看网卡状态
ip route 查看路由表和默认网关

## 网络排查思路
网卡是否启用   ip link
    ↓
是否有 IP 地址 ip addr
    ↓
是否有默认路由 ip route
    ↓
能否访问默认网关 ping -c 4 默认网关
    ↓
能否访问外部 IP ping -c 4 8.8.8.8
    ↓
能否解析域名 ping -c 4 www.baidu.com
    ↓
浏览器是否正常

## 总结问题
1.为什么 ping 8.8.8.8 可以用来排除 DNS 问题？
8.8.8.8是google提供的公共DNS服务器ip 直接访问IP是不需要进行域名解析的 如果能访问 说明能访问外网 但是dns可能有问题 域名解析失败 如果不能 说明可能是网卡、路由、网关、外网连接的问题
2.Destination Host Unreachable 和 100% packet loss 分别说明什么？
第1个说明 本机或中间设备无法找到通往目标的有效路径 第2个说明 没有收到任何ICMP回应
3.为什么必须先测试默认网关？
因为要先从近到远进行测试 数据包是一层一层递出去的
Windows 的 VMnet8 地址和 Ubuntu 的 IP 为什么要处于同一个网段？
因为Ubuntu 的 IP 和 VMware NAT 网关必须处于同一子网，Ubuntu 才能直接把数据帧发送给网关
为什么把 Ubuntu 从静态 IP 改为 DHCP 能解决问题？
改为DHCP后 Ubuntu 会向 VMware DHCP 服务请求当前 NAT 网段中的有效 IP、子网掩码、默认网关和 DNS 配置，从而替换已经失效的静态配置。
ip addr 和 ip route 分别查看什么？
ip addr 查看ip地址和网卡   ip route 查看完整的路由表 其中可能包含默认网关
这次为什么不应该一开始就修改 DNS？
因为可能不是dns的问题
如果以后再次遇到类似问题，你会按什么顺序排查？
1.ip link  # 网卡是否启用 2.ip addr  # 是否获得正确 IP 3.ip route   # 是否存在默认路由 4.ping -c 4 <默认网关>   # 能否到达 VMware 网关 5.ping -c 4 8.8.8.8   # 能否访问外部 IP 6.getent hosts www.baidu.com # DNS 能否解析 7.curl -I https://www.baidu.com # 实际 Web 连接
## ICMP是什么
Internet Control Message Protocol
互联网控制消息协议
用于网络设备之间 传递 连通性测试 错误通知 路由和传输状态信息 
注意：有的服务器禁用ICMP 但是可以使用HTTP 和 HTTPS
## 路由表是什么
操作系统保存的数据包转发规则 路由表决定 一段信息发出时 发的目标地址 下一跳是怎样的 下一个地址发往哪里
## VMnet8和网关的区别
VMnet8是一个虚拟网络接口 网关是负责将数据包转发到其他网络的设备或者地址
